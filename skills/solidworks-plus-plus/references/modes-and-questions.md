# 两种模式与提问规则

本文件定义每次任务开工前的固定动作：确认对象 → 判定模式 → 收集必要信息 → 决定是否提问（可多轮）→ 形成任务卡。
目标：低成本模型也能按同一套确定性流程工作，不靠临场猜测。

## 1. 模式判定（先确认对象，再判模式）

| 模式 | 触发说法 | 尺寸策略 | 交付底线 |
|---|---|---|---|
| **A 示意模式** | “示意”“大概”“不用精确”“先看个样子”“比例对就行” | 不问**具体数值**；但“做的是什么、长什么样、几个零件”不清楚时照样要问（见 2.1） | 可编辑模型 + 等轴测预览 + 假设清单 |
| **B 精确模式** | “精确”“按图”“完整”“可加工”“尺寸要对”“出工程图” | 图纸尺寸优先；缺失就提问 | 模型 + 参数表 + 四视图 + 审查报告 + 工程图（如需） |

判定顺序：
0. **对象清不清楚？** “做的是什么、长什么样、几个零件、用在哪儿”有任何一项不清楚 → **先问对象，再判模式**（用 2.3 格式，一轮问清）。两种模式都适用本步，不许凭想象开工。
1. 用户明确说了模式 → 直接用。
2. 用户给了带尺寸的三视图/工程图，且没说是示意 → **B**。
3. 用户只给照片/截图/口头描述 → **A**；若用户要求“精确”，转 B 并说明照片无法保证精度。
4. 仍然无法判断（需求模糊：既像示意又像交付，或没有任何模式线索）→ 用 §1.1 的六段式模板把模式问清，**不许一句带过**。

### 1.1 模式选择提问模板（需求模糊时必用）

需求模糊 = 判定顺序 0–3 都不命中。模式问题是**第一个重大分支**：两种模式的路线、提问范围、交付物完全不同，选错不是改一个参数，是整条路线返工。按 §2.3 固定六段式问，把后果讲透：

```text
问题：这次要 A 示意模式（定性看形状，不抠尺寸），还是 B 精确模式（尺寸精确、完整可交付）？
我的理解：<从用户原话找证据并引用：说“尺寸随意/大概/先看个样子”→ 倾向 A；说“按图/可加工/出工程图”→ 倾向 B；两类线索都有 → 把冲突点列出来>
为什么关键：两种模式后续路线完全不同——
  A：不问具体数值，只问对象/结构/拓扑（§2.1）；交付 模型 + 等轴测预览 + 假设清单。
  B：按图施工，图纸/描述缺的每个关键尺寸都会逐项提问（§2.1 七条，可多轮），直到确认或授权；交付加 参数表 + 四视图 + 审查报告 + STEP/工程图。
  选错 = A 白问一堆尺寸浪费时间，或 B 交付一个尺寸站不住的模型。
选项：
  A) 示意模式 → 不问你任何具体数值；形状/比例/拓扑我定并标 assumed；最快，只供定性看
  B) 精确模式 → 尺寸可追溯、可交付；缺失的关键尺寸我会多轮停下问你，需要你逐项回答或授权“你定”
  C) 先示意后精确 → 先按 A 快速出模型确认形状，再转 B 补尺寸（补尺寸时说明哪些零件复用、哪些重建）
推荐：<基于证据；原话有“尺寸随意/大概”推荐 A，有“按图/出图/可加工”推荐 B，两类线索都有推荐 C>（若选错，返工范围是 …）
```

- 优先用结构化提问工具（如 `AskUserQuestion`）：A/B/C 做成卡片，推荐项放第一位并标注“推荐”。
- **选 B 等于用户接受后续多轮尺寸提问**：确认时明说“选 B 后，图纸缺的每个关键尺寸我都会停下来问你”，让用户对提问量有预期；不许把 B 的逐项提问省成 A 式的“顺便确认一下”。
- 模式只问一次，判定后全程生效；但**过程门禁照常**（§2.5）：执行中新出现的重大分支仍要停下问。模式本身不重问，除非需求性质变了（示意件中途改要出图 → 转 B，并立刻补 B 的尺寸提问）。
- 用户已明说模式（判定顺序 1 命中）→ 不套模板，按第 1 节表格直接确认。

## 2. 提问规则（grill-me 式：不确定就问，问清为止）

**总原则：关键信息不确定 → 先问，不猜。** 只有用户明确说“你定/随便”，或确认“这项确实确定不了”，才允许采用推荐值继续，并如实标记来源。允许多轮提问，直到关键项全部确定或用户授权。

提问不是开工时的一次性动作：决策门禁贯穿全程（§2.5），过程中发现重大分支要立即停下问，不许攒到交付。

### 2.1 什么时候必须问

满足以下任一条**必须提问**，不许自行假设（不许“猜一个值先建着”）：

1. 答案会改变**拓扑**：单件 / 焊接件 / 装配体；实体数量；是否需要配合。
2. 答案会改变**接口**：孔距、轴径、螺纹规格、法兰标准、安装面。
3. 答案会改变**总体包络**或关键功能尺寸，且图纸/图片无法推导。
4. 用户目标本身冲突：既要“像照片”又要“可制造”，且二者不可兼得。
5. **对象本身不清楚**：做什么、长什么样、几个零件、用在哪儿——先问清对象再谈建模。
6. **关键结构读不懂**：图上有但看不清/读不懂的形状、孔位、凸台、筋——把自己的理解说出来问用户“对不对”，不许按“看起来像”建模。
7. **输入来源互相冲突**：照片与照片、照片与文字描述给出不同结构/尺寸 → 把冲突点列出来问用户取舍，不许自行取其一（用户已明确授权设计自由度的除外）。
8. **参考图任务的性质**：要 1:1 复刻照片里的物体，还是只要结构/风格相似（允许自行设计）？复刻时比例基准是哪个已知尺寸/标准件？照片里没有任何已知参照物 → 先问主尺寸，不许默认“就当 100 mm”。
9. **尺寸来源冲突**：同一尺寸在不同视图、标题栏、技术要求里给出互相矛盾的值（如 φ40 与 φ22 沉孔、总长 130 与分段和 120）→ 列出冲突点和各自出处，问用户取舍；不许静默取其中一个。
10. **工程图交付前**：材料、未注公差等级、图号、零件名称、设计/审核等标题栏字段从哪来？没有来源就列为未决项问用户，**不许自己发明**（不许默认 45 钢、不许自定 ±0.1）。
11. **可购买件**：轴承/螺栓/齿轮/弹簧等外购件的规格系列、是否允许用占位件、缺货时的替代方案——先查标准表，查不到就问，不许画个形状相似的件当标准件交付。
12. **修改已有模型/图纸**：旧版本是否保留、新版本命名规则、交付格式（SLDDRW / PDF / DWG）——覆盖上一轮交付是黑名单项，动手前问清。

**设计侧分界线**（某个缺失尺寸该不该问）：过 `expert-thinking.md` §4.3 关键尺寸五判据——命中“决定功能/配合、与标准件互换、影响强度、影响装配、约束整机外形”任一条 → 必问；否则进 §4.4 可推荐清单，按 §4.5 经验公式推荐并注明出处与适用条件。

### 2.2 什么时候不许问

- 能由图纸尺寸链推导出的尺寸（推导后标 `derived`，公式写进参数表）。
- 不影响拓扑和接口的圆角、倒角、装饰细节（用常规值，标 `assumed`）。
- 标准件可以直接按标准选的（M6 粗牙、6204 轴承、45# 钢等，标 `standard`）。
- 模式 A 下的**具体数值**不问；但对象、结构、拓扑问题照问（见 1 节第 0 步）。
- 用户已经回答过的问题，不许重复问。

### 2.3 提问格式（固定六段）

```text
问题 1/4：<一句话问题，点名具体对象/尺寸/部位>
我的理解：<当前理解或猜测 + 依据：哪张图、哪个部位、量出的值>
为什么关键：<不确认会走哪条错误路线、返工哪些步骤>
选项：A) <具体做法> → 后果  B) ...（2–4 个，互斥，每个写清后果）
推荐：A（理由；若选错，返工范围是 …）
```

- 一次最多 4 个问题，按重要性排序。**一轮问完还有关键不确定项 → 再问下一轮，多次问是被鼓励的。**
- 每个问题必须有推荐值和默认动作；推荐值**未经确认不得直接使用**。
- 用户说“你定/随便”→ 采用推荐值，参数表标记 `source=user_delegated`。
- 用户说“这项确定不了/图上没有”→ 采用推荐值，标记 `source=assumed`，交付时列出。**只有经过这种人为确认后才允许“编”。**
- 用户不回答却要求继续 → 重申一次风险（“这两项不确定会导致 X 错误，请回答或授权推荐值”）；用户仍坚持继续 → 视为授权，采用推荐值并标记 `source=user_delegated`。
- 每个答案写入任务卡，不重复问同一项。
- 有结构化提问工具（如 `AskUserQuestion`）时优先使用：把选项做成可选卡片，推荐项放第一位并标注“推荐”。

### 2.4 停止条件

剩余未知量只影响非关键细节（圆角大小、装饰纹理、非配合孔位微调）→ 停止提问，直接建模并记录假设。
2.1 的七条关键项未确定时**不得停止提问**，除非用户明确授权或确认“确定不了”。
本轮的停止条件只对当前阶段生效；进入新阶段（§2.5 G1）时重新评估。过程中出现重大分支不得以“快到交付”为由跳过提问。

### 2.5 决策门禁：提问贯穿全程（不只在开工）

三道门禁：

- **G0 开工门禁**：对象、模式、交付物（第 1 节 + §2.1）。
- **G1 阶段门禁**：每次进入新阶段前（清点输入 → 形体分析 → 特征建模 → 装配/配合 → 出图/导出/仿真），先扫一遍任务卡 `OpenQuestions`——上一阶段执行中冒出来的未定项、本阶段新引入的分支，当场问清再动手。典型分支：铰链位置/装配位姿（决定多个零件的开孔与配合）、图幅与投影角（决定出图路线）、导出格式与命名（决定交付产物）。
- **G2 过程门禁**：执行中发现新歧义 → 立即停下提问。重大分支**当场单独问**，不许合并延迟；小问题攒批（每轮 ≤4）但不得跨阶段拖延，也不许攒到交付。

**重大分支判据**（命中任一条 = 必须当场问，不许自己拍板）：

1. 决定后续 ≥2 个步骤怎么做（例：铰链位置 → 背板孔位、托钩定位、装配配合全跟着变）。
2. 选错要重建零件/重做装配/重新出图（返工成本 > 改一个参数）。
3. 改变拓扑/接口/包络（§2.1 七条）。
4. 用户偏好类且选项互斥（材料、表面处理、颜色、命名、文件格式）。
5. 多个输入来源冲突且都影响结构（§2.1 第 7 条）。

### 2.6 提问质量自检（每条问题发出前过一遍）

- [ ] 选项互斥且基本穷尽常见做法？每个选项写清了后果？
- [ ] “我的理解”带证据（图号/部位/数值），不是空泛复述？
- [ ] “为什么关键”写清了会返工哪些后续步骤？
- [ ] 有推荐值，且写清用户不答时的默认动作？
- [ ] 问题来自**这次输入的实际观察**，不是用配方/案例默认值顶替？——背答案预防：拿不出“这个值来自用户输入”的证据，就是该问的。
- [ ] 参考图任务写清了“复刻 vs 灵感”和比例基准了吗？
- [ ] 输入里互相矛盾的尺寸逐条列出来问取舍了吗？
- [ ] 材料、公差等级、标题栏字段的来源问清了吗（没有来源就标未决，不发明）？

## 3. 参数来源标签（参数表必须带）

| 标签 | 含义 | 精度处理 |
|---|---|---|
| `explicit` | 图纸/用户明确给出 | 按值，公差按图纸 |
| `derived` | 由尺寸链、几何关系推导 | 按推导值，记录公式 |
| `standard` | 国标/标准件/常用系列 | 按标准值 |
| `user_confirmed` | 用户回答确认 | 按确认值 |
| `user_delegated` | 用户授权“你定” | 按推荐值 |
| `assumed` | 经用户确认“确定不了”后采用的推荐值（关键项）；或 2.2/2.4 允许不问的非关键细节常规值（如装饰圆角 R2） | 按推荐值/常规值，交付时列出 |
| `estimated` | 从图片比例估算 | 按估算值，容差 2–5% |

## 4. 任务卡（建模前生成，模式 B 需确认）

```yaml
Mode: A | B
InputType: three_view | photo | existing_model | text_brief
OpenQuestions: [尚未确定的关键项；建模前必须为空或已获用户授权]
Deliverables: [sldprt, step, slddrw, pdf, preview, report]
Units: mm
Coordinate: X=长度, Y=高度, Z=深度; Front Plane=XY
Envelope: {length: , width: , height: }
BodyCount: 1
FeatureGroups:
  - {name: 底板, type: extrude, key_dims: [...], depends: []}
  - {name: 主孔, type: cut, key_dims: [...], depends: [底板]}
FixedParameters: [...]
Assumptions: [...]
Validation:
  - 包围盒误差 <= 0.1 mm（B）/ 5%（A）
  - 实体数 == 1
  - 关键特征名存在
  - 四视图预览非空且方向正确
```

**机器可读版本**：把上面的任务卡落成 `<workdir>\task_card.json`，字段定义见
`references/task-card-schema.md`，用 `scripts/check_task_card.py` 检查（模式、
六段式提问、参数来源追溯、G0/G1/G2 门禁、交付说明）。建模前 `--stage model`，
交付前 `--stage delivery`；不通过不许动手/宣布完成。YAML 版适合给人看，
JSON 版给脚本查，两者内容必须一致。

## 5. 检查点

- 🔴 **CHECKPOINT 1（模式与交付）**：模式判定后，用一句话向用户确认“对象理解 + 模式 + 交付物”。模式是问出来的（§1.1）时，确认句必须重申两种模式的差异与已选模式的后果：A = 不问数值、只问结构；B = 缺失的关键尺寸会逐项提问。模式 A 可直接继续；模式 B 若所有关键尺寸均 `explicit`，也可直接继续。
- 🔴 **CHECKPOINT 2（参数与特征）**：存在任何未确定的关键项（含模式 A 的对象/结构问题）时，先提问并展示任务卡和问题清单，等用户回答或授权后再建模。
- 🔴 **阶段门禁（G1/G2）**：进入新阶段前重扫任务卡 `OpenQuestions`；执行中发现重大分支立即停下问（§2.5）。
- 🔴 **CHECKPOINT 3（交付）**：展示模型预览、包围盒、假设清单和文件路径；工程图任务还要展示 PDF/PNG 预览。

## 6. 反例

- ❌ 模式 A 还追问“板厚到底多少”。
- ❌ 一次抛出十几个尺寸问题。
- ❌ 用户答“你定”后继续追问。
- ❌ 把 `assumed` 尺寸写进交付说明时隐瞒来源。
- ❌ 图纸已有孔距还去问用户。
- ❌ 拓扑没确认就开始建模，最后发现应该是装配体。
- ❌ 关键尺寸不确定就“猜一个值”开始建模——必须先问；只有用户确认“确定不了”或授权后才可编。
- ❌ 对象没问清（做什么、几个零件、长什么样）就凭想象建模。
- ❌ 推荐值未经用户确认就直接当答案用。
- ❌ 问了一轮还剩关键不确定项就不再问。
- ❌ 不判断零件实际结构，背配方生搬硬套特征顺序。
- ❌ 把“我猜是/看起来像”当作用户确认的事实。
- ❌ 只在开工问一次，过程中发现新歧义不提问、攒到交付再补“假设”。
- ❌ 重大分支（影响多个后续步骤/返工成本高）自己拍板，不提问。
- ❌ 提问不带依据、不带选项后果，让用户做没有信息量的选择题。
- ❌ 用配方/案例的默认值顶替本应提问的关键尺寸。
- ❌ 需求模糊时用一句“你要大概的还是精确的？”确认模式，不说明两种模式的提问范围、交付物和选错后果。
- ❌ 用户选了 B 却不对缺失尺寸逐项提问，攒到交付再补“假设”（B 的 grill-me 全程有效）。
