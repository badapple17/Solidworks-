# SolidWorks++ · SolidWorks 建模与出图技能（非官方）

> **同一个内核，多一套工程库。**
> 让**低成本模型**也能稳定交付合格的三维模型与工程图。
> v1.2 · 2026-10-25 · 非官方项目

> **定位说明**：SolidWorks++ 是建立在 SolidWorks API 之上的工程库与工作流层，**不是新的 CAD 内核，也不是 SolidWorks 的修改版**。输出仍是原生 `SLDPRT` / `SLDASM`，任何 SolidWorks 都能打开。
>
> SolidWorks 是 Dassault Systèmes 的注册商标；本项目与 Dassault Systèmes 无隶属、赞助或背书关系。

## 0. 一分钟了解

| 项 | 内容 |
|---|---|
| 输入 | 三视图 / 工程图、照片 / 截图、已有 `SLDPRT` / `SLDASM`、文字需求 |
| 输出 | 可编辑 SolidWorks 零件 / 装配、四视图预览、GB 第一角工程图（`SLDDRW` + `PDF`）、审查报告、参数表 |
| 两种模式 | **A 示意模式**：定性看形状，不抠尺寸；**B 精确模式**：按图施工，尺寸可追溯、可交付 |
| 核心承诺 | **不猜**。关键信息不确定就提问；每个交付都必须过证据门禁 |
| 适用 | Windows + SolidWorks 桌面版（COM），Python 3.9+ |
| 仓库内容 | `skills/solidworks-plus-plus/`（149 个文件的完整技能）+ `showcase/`（6 个由 DeepSeek V4 生成的真实实例） |
| 安装 | `npx skills add badapple17/Solidworks-`，或 `git clone` 后把 `skills/solidworks-plus-plus` 放进本机 skills 目录 |

这个技能不是一份“提示词模板”，而是一套**可执行的工程流程**：模式判定 → 提问 → 任务卡 → 路线文档 → 确定性脚本 → 证据门禁 → 失败分支 → 交付审查。它的目标不是让模型“更会聊天”，而是让能力较弱的模型也能按同一套流程做出**尺寸对、拓扑对、能复查**的模型。

### 0.1 名字里的 `++` 是什么（命名灵感来自 C++）

| `+` | 加的是什么 | 对应内容 |
|---|---|---|
| 第一个 `+` | **标准库** | 41 个确定性脚本：连接、草图、拉伸、旋转、孔、阵列、装配、出图、审查、导出、FEA 判据、任务卡/PDF/一致性检查 |
| 第二个 `+` | **工程规范** | 零件族配方、参数表、验证门禁、失败分支、G0/G1/G2 提问协议 |

这个命名方式确实受到 **C++** 的启发：C 提供语言内核，C++ 在它之上增加了类、模板、标准库和整套工程设施；SolidWorks++ 借用同样的结构——SolidWorks 仍是内核，`++` 是加在 API 之上的脚本库与工程规范。

区别也要说清楚：C++ 是一门新的编程语言，而 **SolidWorks++ 不是新语言，也不是新内核**。它不改变 SolidWorks 的文件格式和建模内核，只改变“怎么稳定地使用 SolidWorks”这一层——**内核仍然是 SolidWorks，模型仍然是原生文件**。

### 0.2 六个实例得出的结论：信息越全越准，越简单越要多问

把 `showcase/` 里六个真实任务放在一起看，正确率和“输入信息量”几乎是一条直线：

| 输入信息量 | 实例 | 结果 |
|---|---|---|
| **高**：零件图 + 装配图 + 明细栏 + STEP 标准件 | 05 减速器、06 齿轮油泵（考试题） | 尺寸可追溯，建造过程几乎不需要补充提问；剩余偏差只来自试卷图自身的尺寸冲突 |
| **中**：多视图 + 标注尺寸 | 01 齿轮、02 轮毂、03 水瓶 | 一轮提问定模式后即可施工，证据链完整 |
| **低**：15 张照片 + “尺寸随意” | 04 折叠手机支架（照片反求） | 结构能读对，但主尺寸、螺钉布局、手机型号都得回头问用户才定得下来 |

两条直接写进技能的规则：

1. **输入越详细、越全面，模型越接近正确。** 图纸齐全时，模型做的是“读数 → 施工 → 验证”，不是“猜”。
2. **简单模型反而更容易发懵和瞎编。** 一个零件很简单、用户又只说“随便做一个/看着像就行”时，信息量和质量要求同时含糊，模型会按常见做法把结构、数量、比例自己补出来。**所以任务越简单、需求越含糊，越要多提问**：至少问清用途/受力、关键接口（孔距、轴径、安装面）、哪些尺寸可自定、质量档位（示意 / 能装配 / 能加工）；四项没答全不开工。

这两条落在 `references/modes-and-questions.md` §2.0（提问强度与输入信息量成反比）和 SKILL.md 黑名单里。展示实例的逐案分析见 [`showcase/README.md`](showcase/README.md) §3。

## 1. 它解决什么问题

低成本模型做 CAD 自动化时，最常出现的不是“不会写 API”，而是下面这些**静默失败**：

- 关键尺寸不确定，先猜一个值建着，最后交付一个“看起来像”的模型；
- 特征返回 `None` 还继续叠加，最后保存成功但模型是坏的；
- 只检查“无报错”，不看预览图，方向反了、孔没切穿都发现不了；
- 出图后尺寸数为 0，却声称“已自动标注”；
- 把估读尺寸标成 `explicit`，用户按图加工时才发现对不上；
- 覆盖上一轮交付文件，返工时找不到基线；
- 只在开工问一次，过程中发现新歧义不提问，攒到交付再补“假设”。

这个技能把这些失败模式逐条编码成**检查点、门禁、失败分支和黑名单**，并用封装好的脚本把 COM 调用固定下来，减少临场发挥。

## 3. 两种工作模式

| 模式 | 触发说法 | 尺寸策略 | 交付底线 |
|---|---|---|---|
| **A 示意模式** | “示意”“大概”“不用精确”“先看个样子”“比例对就行” | **不问具体数值**；但“做的是什么、长什么样、几个零件”不清楚时照样要问 | 可编辑模型 + 等轴测预览 + 假设清单 |
| **B 精确模式** | “精确”“按图”“完整”“可加工”“尺寸要对”“出工程图” | 图纸尺寸优先；缺失的关键尺寸**逐项提问**，可多轮 | 模型 + 参数表 + 四视图 + 审查报告 + 工程图（如需） |

### 模式选择本身就是第一个重大分支

需求模糊时（既像示意又像要交付），技能不会用一句“你要大概的还是精确的？”带过，而是按**固定六段式**把两种模式的后果讲透再问：

```text
问题：这次要 A 示意模式（定性看形状，不抠尺寸），还是 B 精确模式（尺寸精确、完整可交付）？
我的理解：<从用户原话找证据并引用：说“尺寸随意/大概”→ 倾向 A；说“按图/可加工/出工程图”→ 倾向 B>
为什么关键：两种模式后续路线完全不同——
  A：不问具体数值，只问对象/结构/拓扑；交付 模型 + 等轴测预览 + 假设清单。
  B：按图施工，缺失的每个关键尺寸都会逐项提问，直到确认或授权；交付加 参数表 +
     四视图 + 审查报告 + STEP/工程图。
  选错 = A 白问一堆尺寸浪费时间，或 B 交付一个尺寸站不住的模型。
选项：
  A) 示意模式 → 不问你任何具体数值；形状/比例/拓扑我定并标 assumed；最快，只供定性看
  B) 精确模式 → 尺寸可追溯、可交付；缺失的关键尺寸我会多轮停下问你
  C) 先示意后精确 → 先按 A 快速出模型确认形状，再转 B 补尺寸
推荐：<基于证据；若选错，返工范围是 …>
```

选择 B 时，技能会**明说**“后续缺失的每个关键尺寸都会停下来问你”，让用户对提问量有预期；不会把 B 的逐项提问省成 A 式的“顺便确认一下”。

## 4. 提问机制（参考 grill-me 的“问清为止”）

### 4.1 总原则

> **关键信息不确定 → 先问，不猜。**
> 只有用户明确说“你定/随便”，或确认“这项确实确定不了”，才允许采用推荐值继续，并如实标记来源。

### 4.2 什么时候必须问

满足任一条必须提问，不许自行假设：

1. 答案会改变**拓扑**：单件 / 焊接件 / 装配体；实体数量；是否需要配合。
2. 答案会改变**接口**：孔距、轴径、螺纹规格、法兰标准、安装面。
3. 答案会改变**总体包络**或关键功能尺寸，且图纸/图片无法推导。
4. 用户目标本身冲突：既要“像照片”又要“可制造”，且二者不可兼得。
5. **对象本身不清楚**：做什么、长什么样、几个零件、用在哪儿。
6. **关键结构读不懂**：图上有但看不清/读不懂的形状、孔位、凸台、筋。
7. **输入来源互相冲突**：照片与照片、照片与文字描述给出不同结构/尺寸。
8. **参考图任务的性质**：1:1 复刻还是只要结构/风格相似？复刻的比例基准是哪个已知尺寸/标准件？
9. **尺寸来源冲突**：同一尺寸在不同视图、标题栏、技术要求里互相矛盾 → 列出冲突点问取舍。
10. **工程图字段来源**：材料、未注公差等级、图号、设计者——没有来源就问，不许自己发明。
11. **外购件规格**：轴承/螺栓/齿轮的系列、是否允许占位件、缺货时的替代方案。
12. **改已有文件**：旧版本是否保留、新版本命名规则、交付格式（SLDDRW / PDF / DWG）。

### 4.3 决策门禁：G0 / G1 / G2

| 门禁 | 时机 | 动作 |
|---|---|---|
| **G0 开工门禁** | 每个任务开始时 | 确认对象、模式、交付物；未定项进任务卡 `OpenQuestions` |
| **G1 阶段门禁** | 每次进入新阶段前（清点输入 → 形体分析 → 特征建模 → 装配/配合 → 出图/导出/仿真） | 重扫 `OpenQuestions`，本阶段新引入的分支当场问清再动手 |
| **G2 过程门禁** | 执行中发现新歧义 | 立即停下提问；重大分支**当场单独问**，不许合并延迟，也不许攒到交付 |

**重大分支判据**（命中任一条 = 必须当场问，不许自己拍板）：

1. 决定后续 ≥2 个步骤怎么做；
2. 选错要重建零件 / 重做装配 / 重新出图（返工成本 > 改一个参数）；
3. 改变拓扑 / 接口 / 包络；
4. 用户偏好类且选项互斥（材料、表面处理、颜色、命名、文件格式）；
5. 多个输入来源冲突且都影响结构。

### 4.4 六段式提问格式

```text
问题 1/4：<一句话问题，点名具体对象/尺寸/部位>
我的理解：<当前理解或猜测 + 依据：哪张图、哪个部位、量出的值>
为什么关键：<不确认会走哪条错误路线、返工哪些步骤>
选项：A) <具体做法> → 后果  B) ...（2–4 个，互斥，每个写清后果）
推荐：A（理由；若选错，返工范围是 …）
```

- 一次最多 4 个问题，按重要性排序；一轮问完还有关键不确定项 → **再问下一轮**。
- 每个问题必须有推荐值和默认动作；推荐值**未经确认不得直接使用**。
- 有结构化提问工具（如 `AskUserQuestion`）时优先使用：选项做成卡片，推荐项放第一位并标注“推荐”。
- 发出前过 §2.6 自检：选项互斥且写清后果？我的理解带证据？为什么关键写清返工步骤？有推荐值和默认动作？问题来自**这次输入的实际观察**，不是配方默认值顶替？

### 4.5 真实例子

- **手机支架**：底座直径从用户俯视图按标尺实测约 10.3 cm（原估 Ø110 偏大，改为 Ø104）；螺钉数量/布局由用户明确指定为“3 颗绕圆心 120° 均布，落在脚垫之间”，不按照片猜；U 型座骑在转盘边缘而非圆心，是照片观察后向用户确认的结构判断。
- **车轮**：v1/v2 只做了单面轮辐，用户反馈“轮子只有一面，另一边是空的”；v3 改为前后镜像双面结构，辐窗/中心孔/螺栓孔贯穿切除，两面完全对称。这是 G2 过程门禁的典型场景：用户的反馈改变了拓扑，必须停下重建，而不是在旧模型上补装饰。
- **塑料瓶**：用户只给“百岁山风格”的文字需求，没有尺寸。技能按 A 模式处理：尺寸作为设计自由度（`user_delegated`），但肩部相切关系、壁厚、颈/口尺寸等**结构约束**必须明确记录在参数表和交付说明里。

### 4.6 反例（出现即返工）

- ❌ 需求模糊时用一句“你要大概的还是精确的？”确认模式，不说明两种模式的提问范围、交付物和选错后果。
- ❌ 用户选了 B 却不对缺失尺寸逐项提问，攒到交付再补“假设”。
- ❌ 关键尺寸不确定就“猜一个值”开始建模。
- ❌ 一次抛出十几个尺寸问题。
- ❌ 用户答“你定”后继续追问。
- ❌ 推荐值未经用户确认就直接当答案用。
- ❌ 只在开工问一次，过程中发现新歧义不提问。
- ❌ 重大分支自己拍板，不提问。
- ❌ 提问不带依据、不带选项后果，让用户做没有信息量的选择题。
- ❌ 用配方/案例的默认值顶替本应提问的关键尺寸。

## 5. 弱模型兜底机制

### 5.1 质量分层：L1 是地板，不是天花板

| 层级 | 适用 | 必读 | 交付线 |
|---|---|---|---|
| **L1 保底** | 能力较弱 / 上下文受限 | `SKILL.md` + 路线文档 + `references/quick-snippets.md` + 命中的配方 | 第 5 节门禁全部通过；几何、实体、孔、图纸不得错 |
| **L2 专业** | 中等及以上模型 | L1 + `part-modeling.md`、`feature-strategy.md`、`expert-thinking.md`、`drawing-standards.md`、`standard-parts.md`、`pitfalls.md` | 加：特征顺序与选型、公差/配合、表面粗糙度、标准件、GB 视图规范 |
| **L3 专家** | 强模型 / 复杂件 | 全部 references + `case-library.md` + 题库案例 | 加：复杂曲面、装配、运动、工艺性审查 |

规则：**不靠删知识来降门槛**。弱模型照 L1 做也必须能交付合格件；强模型在 L1 通过后继续 L2/L3，不得被 L1 的简化步骤限制；不得为了省 token 删除或跳过 L2/L3 的检查项。

### 5.2 确定性脚本 + 返回值检查

- 所有长度输入用毫米，调用 `mm()`；API 内部单位是米。
- 草图必须闭合；每个特征调用后检查返回值是否为 `None`。
- 先加后减；圆角/倒角最后做。
- 特征命名写清用途和关键尺寸（如 `02_BORE_D36`），用封装的 `name=` 参数，不另写改名代码。
- 方向不确定时先做一个特征，回读 `GetPartBox(True)` 再继续。
- 不用屏幕坐标选面/选边；用几何条件或特征名。

### 5.3 验证门禁（所有任务）

| 门禁 | 通过标准 | 证据 |
|---|---|---|
| 文件 | `.SLDPRT` 存在且能重新打开 | 文件大小 > 0 |
| 几何 | 包围盒与总体尺寸一致 | B：≤ max(0.1 mm, 0.2%)；A：≤ 5% |
| 体积 | 与参数表手算体积差 ≤ 0.1% | `collect_geometry_measurements()["volume_mm3"]` |
| 实体 | 实体数等于任务卡 `BodyCount` | `GetBodies2(0, False)` |
| 特征 | 关键特征存在、无重建错误 | `ForceRebuild3(False)` + 特征树 |
| 孔 | 孔径/孔位与图纸一致 | `collect_geometry_measurements()` |
| 视觉 | 四视图预览方向、比例、特征正确 | `run_review()` 导出的 BMP |
| 图纸 | 视图数、尺寸数、布局、PDF | `_drawing_report.json` + PDF 首屏 |
| 图纸 PDF | `check_drawing_pdf.py` 无 fail（悬空尺寸、无引出线、越界、视图重叠） | `pdf_check` 报告 |
| 流程 | 任务卡过 `check_task_card.py`；交付时 handoff 证据齐全 | `task_card.json` + 检查输出 |

`evaluation.status` 不是 `pass` 时**禁止宣布完成**；先修复并重新生成。

### 5.4 失败分支表（节选）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 连接失败 / RPC 不可用 | 确认 SolidWorks 已启动、无残留进程；用 `--visible` 重试一次 | 重启 SolidWorks 后再连一次；仍失败就停止并告知用户，不要连续重试 |
| 草图未闭合 / 拉伸返回 `None` | 检查轮廓自交、漏边；先用最简单矩形验证 | 重画闭合轮廓；导出草图截图目视检查；仍失败则停下问用户 |
| 切除方向反了 | 按材料所在侧翻转 `direction`，回读包围盒 | 在加工面建偏置面，只做一个试验孔；确认无误再批量 |
| 孔位整体偏移 | 检查 Top Plane 纵轴符号（`v = −Z`） | 改中心对称布局，或把孔系移到 Front Plane；回读 `position_mm` 逐项比对 |
| 视图创建返回 `None` | 用 `GetModelViewNames()` 读本机名，重试一次 | 逐视图单独创建并记录 `failures`；缺视图不得交付 |
| 图纸空白 / 视图在纸外 | 查 `sheet_size_verified` 与 `actual_size_m`；SW2023 A3 码是 8 | 用同码重设图幅并重排布局；仍空白就打开 `.SLDDRW` 人工检查模板 |
| 尺寸数为 0 | 回模型对每个草图调用 `auto_dimension_sketch()`，重新出图 | 检查特征树有无 DisplayDimension；仍为 0 就停下说明原因 |
| 预览空白 | 检查 PDF 是否落盘（SaveAs 可能返回 False 但文件已写入） | 重新导出并渲染；仍空白就打开 `.SLDDRW` 截图，不交付空白预览 |
| 圆角失败 | 跳过圆角，保留直边，交付说明标注“外观圆角未应用” | 改用草图圆角/圆角矩形；不要为圆角重做主体超过一次 |

### 5.5 黑名单（出现即返工）

不判定模式就直接建模；把虚线当外轮廓；用屏幕坐标选边选面；猜测未封装的 COM 签名和枚举值；草图未闭合就拉伸；圆角在主体切除之前做；只保存不审查；用第三角布局交付国内加工图；尺寸数为 0 却声称“已自动标注”；覆盖上一轮交付文件；隐瞒 `assumed` / `estimated` 来源；关键信息不确定就瞎猜；推荐值未经确认就使用；不判断结构就背配方；只在开工问一次；重大分支自己拍板；工程图 PDF 没过 `check_drawing_pdf.py` 就宣布出图完成；任务卡没过 `check_task_card.py` 就宣布完成；检查没跑就写 pass；照片复刻没有比例基准就估尺寸；自己发明公差、材料或标题栏字段。

### 5.6 可重复验收用例

`test-prompts.json` 共 **18 个用例**，其中 **7 个黄金用例**（每次改技能必跑）：

## 6. 训练过程

这个技能是在 2026-10-24 至 10-25 的两天里，用**真实题库 + 工程手册 + SolidWorks 真机**训练出来的。训练目标不是“让模型背更多 API”，而是把**读图、定特征顺序、验证结果**的经验沉淀成可执行文档和脚本。

### 6.1 数据来源

| 来源 | 规模 | 用途 |
|---|---|---|
| 阿奇 SolidWorks 40 道练习题 | 105 个答案零件、8 个装配、4 个工程图 | 特征树统计、建模顺序、装配/出图案例 |
| 64 道三维建模题 | 66 个答案零件 | 图 → 模型完整复建（含黄金用例 001） |
| 全国成图大赛 1–15 届 | 305 个零件、28 个装配、32 个工程图、29 个 PDF | 复杂件、装配、工程图模式 |

| CATICS 3D01–3D18 | 217 张图 | L3 读图练习（无答案模型，不入自动回归） |
| 机械设计 118 本 + 机械基础 54 本 | 172 本，171 本有文字层 | GB 制图规范、标准件、公差/配合、粗糙度、齿轮/键/轴承/弹簧画法 |

### 6.2 训练流水线

1. **整合**：把 `solidworks-automation`、`solidworks-cad`、`solidworks-planning-governance` 三个旧技能合并成**一个执行权威**，避免模型在多个入口之间摇摆。
2. **特征树挖掘**：解析答案文件的特征树与尺寸，统计零件族的特征顺序、草图角色、终止条件。SW100/SW150 的实体件中 97% 以拉伸为主特征。
3. **手册蒸馏**：从 172 本手册提炼 `drawing-standards.md`（GB 视图/尺寸/公差/粗糙度/技术要求）与 `standard-parts.md`（螺栓、键、轴承、齿轮、弹簧、链轮、销）。
4. **教材 OCR**：8 册 SolidWorks 2024 教材全部是扫描件，用 Windows 自带中文 OCR（200 dpi，批处理 25 页）转文本；按 70 页切块，提炼成 29 份 digest，合成 `surfacing.md`、`motion-study.md`、`feature-strategy.md`、`assembly.md`、`verification.md`、`piping.md` 六块知识。
5. **配方库**：按零件族沉淀 5 个固定配方（板件通孔、台阶轴、法兰盘、连杆/杠杆、支架筋），给出特征顺序、参数表和验证点。
6. **真机黄金用例**：在 SolidWorks 2023 SP0.1 上跑通 001 连杆、板件复合孔、法兰沉孔、A3 第一角出图；记录包围盒、体积、孔数、视图数、尺寸数作为回归基线。
7. **弱模型可用性测试（两轮）**：
   - 第 1 轮：受限模型只读 5 篇 L1 文档，脚本真跑通过（包围盒 120×80×12、6 圆柱面、体积 99794.337 mm³），但暴露 `extrude_cut` 方向语义写反——全靠 `auto_flip` 兜底。
   - 真机锁定：8 组对照实验（`auto_flip=False`）确定 `extrude_boss` 与 `extrude_cut` 的 `direction` 语义相反，修正 18 个文件。
   - 第 2 轮：同样只读 L1，真机通过，日志**无“自动翻转”**，各项门禁一致。
8. **darwin-skill 多轮优化**：用 3 名独立 paired judge 比较改前/改后，3-0 `keep`，采纳 judge 的圆角不等式、对称还原系数两处修正。
9. **可移植化（2026-10-25）**：全包清除本机路径，文档统一 `<skill>` / `<workdir>` 占位符；安装目录、图幅模板、类型库改为自动发现；示例输出改为脚本旁的相对目录。
10. **提问协议升级（2026-10-25）**：加入 G0/G1/G2 决策门禁、模式选择六段式模板、提问质量自检和背答案预防。
11. **实例生成**：用 DeepSeek V4 系列模型在真实对话中完成六个实例（齿轮、车轮、塑料瓶、手机支架、减速器、齿轮油泵），保留建造脚本、输入分析、预览和审查证据。
12. **大装配实盘（2026-10-25）**：用两道考试题验证装配与上色路线——05 减速器（10 零件 + 3 套装配 + 3 张工程图）和 06 齿轮油泵（19 零件 + 3 套装配，每套 26 组件）。吸收的经验：变换矩阵列主序与米制平移、组件级透明上色回读重试、干涉按组合登记上限、圆弧轮廓禁用折线近似。
13. **交付文件锁修复（2026-10-25）**：定位到交付后用户打不开文件、必须重启电脑的根因——自动化启动的 SolidWorks 实例**不注册进 ROT**（`GetActiveObject` 失败），但 `Dispatch` 会复用它；`CloseDoc(装配体)` 后依赖零件仍持有文件锁。修复：`connect_solidworks` 登记本进程启动的实例并注册 `atexit` 释放，`SolidWorksSession.finish()` 关闭全部文档并退出自有实例；新增 `sw_release.py` 供手动回收。**用户自己启动的实例永不退出。**
14. **提问结论固化（2026-10-25）**：六个实例复盘出“输入信息量 ↔ 正确率”的关系，新增 `modes-and-questions.md` §2.0：简单件 + 含糊质量要求必须多问（用途、关键接口、可自定尺寸、质量档位四项），简单任务不豁免形体分析。

### 7.1 六个实例的结论

- **输入越详细、越全面，建出的模型越接近正确。** 05/06 有零件图、装配图、明细栏和 STEP 标准件，建造过程几乎不需要追加提问；01–03 靠多视图 + 标注尺寸，一轮提问定模式即可施工；04 只有照片和“尺寸随意”，主尺寸、螺钉布局、手机型号都必须回头问用户。
- **简单模型反而更容易发懵、瞎编。** 零件简单 + 用户要求含糊（“随便做一个”“看着像就行”）时，信息量和质量要求同时缺失，模型会按常见做法自行补结构、补数量、补比例。**任务越简单、需求越含糊，越要多提问**：至少问清用途/受力、关键接口、可自定尺寸、质量档位四项，未答全不开工。
- 这两条已经进入技能正文（`references/modes-and-questions.md` §2.0 + SKILL.md 黑名单），不是 README 里的口号。

> ✅ 齿轮实例的工程图已在 v1.2 用 COM 重出并替换：`check_drawing_pdf.py` 初筛 **pass（0 问题）**，标题栏比例与视图一致（2:1），重复尺寸已去重（10 → 4）。旧 PDF 曾报 10 处 `DIM_NO_LEADER`、2 处 `OUT_OF_FRAME` 和标题栏比例不一致，按门禁作废。详见 [`01-spur-gear/README.md`](showcase/01-spur-gear/README.md)。

## 9. 安装与快速开始

### 9.1 环境要求

- Windows 10/11（SolidWorks COM 仅 Windows）。
- SolidWorks 桌面版。**本仓库真机复测基线：SolidWorks 2023 SP0.1**。2024/2026 是继承自上游 wzyn20051216/solidworks-automation-skill 的实测记录，**本仓库未复测**；这些版本按 `pilot` 对待：先跑 `sw_preflight.py` 和黄金用例，再交付。完整口径见 `capabilities.yaml` 的 `version_policy`。

  - 开发机使用 `py -3.12` 启动器；目标机按本机解释器调用。
- 可选：CalculiX（有限元）、AutoCAD（CNC 二维图纸子技能）；不装不影响主路线。

## 11. 已知限制

1. **不是工程计算替代品**：齿轮实例未做变位、齿根圆角、公差与强度校核；FEA 章节是求解器无关的方法与判据，不是认证报告。
2. **复杂曲面 / 模具型腔 / 导入无特征史曲面**属于 `reference_only` / `pilot` 能力，必须人工审查。
3. **Routing 不自动布线**：`piping.md` 提供线路组织、配件拓扑、折弯/直段、验收与 BOM 的人工流程，不含 Routing API。
4. **照片反求只保证拓扑与比例**，不保证尺寸；关键配合尺寸仍需用户确认或实测。
5. **工程图 PDF 在齿轮和减速器实例中提供**：01 有 A3 零件图，05 有 A2 装配图 + 2 张 A3 零件图；02–04、06 未出图。齿轮 PDF 已通过 `check_drawing_pdf.py` 机器初筛（0 问题），但只标了 4 个主参数；05 装配图的明细栏有 001/005 两项因试卷缺图保留占位。两者都不是完整加工尺寸链。
6. **单看 PDF 无法验证视图真实比例**：`check_drawing_pdf.py` 只能读标题栏比例并与 `_drawing_report.json` 比对；没有报告时该项记为 `SHEET_SCALE_UNVERIFIED`，不能算通过。SW2023 创建视图会把图面比例重置为 1:1，出图脚本必须在视图创建后重设比例（v1.2 已修）。
7. **电气基础/高级教材未提炼**：与机械建模无关，只保留 OCR 原文。
8. **中文优先**：文档与提问模板以中文为主；英文用户可读 SKILL.md 的英文接口说明与脚本注释。
9. **SolidWorks 版本差异**：SW2023 的 A3 图幅码、`extrude_cut` 方向语义、`SetTransformAndSolve2` 旋转限制等已实测；其他版本请先跑黄金用例再判断。
10. **05/06 的装配是静态定位**：组件由变换矩阵放置，没有配合、没有运动算例；05 的 12 处干涉是**试卷图自身尺寸冲突的登记**，不代表可制造配合。
11. **05 缺 XXJSQ-001/005 两件**（试卷只有明细条目、无零件图），装配图明细栏保留占位；06 不提供工程图。
