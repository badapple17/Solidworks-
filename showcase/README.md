# SolidWorks++ 实战实例（showcase）

四个**真实任务**，不是演示玩具。它们由 **DeepSeek V4 系列模型**（低成本档位）在只调用本技能的条件下完成，保留了当时的建造脚本、输入分析、关键预览、审查报告和 PDF。

> **性价比说明**：这些模型不是顶级推理模型反复精修出来的“展示件”，而是低成本模型按技能流程跑出来的交付。能成立靠的是**模式判定、提问、脚本封装和证据门禁**，不是模型本身记住了多少 API。

| 目录 | 任务 | 模式 | 输入 | 核心看点 |
|---|---|---|---|---|
| [01-spur-gear](01-spur-gear/) | 直齿圆柱齿轮 Z24 / m2.5 | A 示意 + 出图 | 文字需求 | 唯一带完整工程图链路的实例：A3 第一角三视图、10 个尺寸、PDF |
| [02-car-wheel](02-car-wheel/) | 汽车轮毂，前后双面 5 辐 | A 示意 | 文字需求 + 用户反馈 | 过程门禁实例：单面 → 双面重建；体积与解析值误差 0.00000% |
| [03-plastic-bottle](03-plastic-bottle/) | 百岁山风格 PET 水瓶 570 ml | A 示意（设计自由度） | 文字需求 | 一次旋转成形；Pappus 解析体积与实测完全对上 |
| [04-phone-stand](04-phone-stand/) | 折叠手机支架（照片反求） | A 照片反求 | 15 张照片中选 3 张 | 8 个零件 + 2 个姿态装配；干涉 0；照片→尺寸的推导链完整 |

## 1. 每个实例都包含什么

所有实例统一使用下面的目录语义：

```text
<case>/
├── README.md              # 任务、参数、验证证据、限制、复现命令
├── *.py                   # 当时的建造 / 验证脚本（已改为可移植路径）
├── *.SLDPRT / *.SLDASM    # 交付模型
├── drawing/               # 工程图 SLDDRW + PDF + 预览 + 报告（仅齿轮）
├── previews/              # 等轴测 / 前 / 上 / 右等预览图与审查报告
├── evidence/              # 几何证据、审查摘要、特征树
├── deliverables/          # 多零件实例的成品目录（仅手机支架）
└── input_photos/          # 输入照片 + 接触表 + 半幅裁切（仅手机支架）
```

`previews/` 里的审查报告是 `run_review()` 的原始输出；`evidence/` 里是额外的几何测量、特征树或参数表。

## 2. 四个实例分别证明了什么

### 01 齿轮：从“示意”走到“可出图”

- 文字需求只给了齿轮类型和大概规格，技能按 **A 模式**处理：不追问具体数值，但把每个取值的来源写进参数表。
- 齿形是**渐开线采样**（每齿 18 点、24 齿共 432 段），不是圆弧 approximation。
- 出图走 **B 路线**（模型 → 图）：`sw_three_view.py` 自动建 A3 第一角三视图、导入模型尺寸、自动排列。
- 证据：包围盒 `65 × 65 × 20`、1 实体、φ20 孔 + φ36 轮毂、审查 100、图纸 `10` 个尺寸、PDF 非空。
- 已知偏差：标题栏“比例”仍是模板的 1:1，与视图实际 2:1 不一致；这不是脚本错误，而是 SW2023 该 GB 模板的限制（重设图纸比例会丢标题栏）。
- 已知缺陷：随包 PDF 跑 `check_drawing_pdf.py` 为 **fail**（10 处 `DIM_NO_LEADER`、2 处 `OUT_OF_FRAME`，φ20 / φ36 的尺寸文字越出视图框）。本包未用 COM 重出这张图；按“复现命令”重跑会得到新 PDF，交付前必须重跑检查并修图或如实披露。

### 02 轮毂：用户反馈触发的 G2 过程门禁

- v1/v2 只做了单面轮辐，用户反馈“轮子只有一面，另一边是空的”。
- 这不是“加个装饰”能修的，属于**拓扑改变**：技能按 G2 门禁停下，重建为前后对称双面结构，辐窗/中心孔/螺栓孔一次贯穿两面。
- 证据：包围盒 `470 × 470 × 200`、1 实体、45 个特征、7 个功能孔、15 个内圆柱面、体积 `7,811,777.122 mm³` 对解析值 `7,811,777.086`（误差 0.00000%）、重新打开复测一致、两面平面面积均 `86,668.805 mm²`、审查 100。
- 这个实例最适合看“证据链”：参数表 → 解析体积 → 实测体积 → 孔位分组 → 重新打开复测。

### 03 水瓶：把“设计自由度”讲清楚

- 用户只给了“百岁山风格”的文字需求，没有尺寸。技能把所有尺寸标为 `user_delegated`（用户授权自定），但**结构约束**（肩部相切、壁厚、颈/口尺寸、容量）必须明确记录。
- 建模路线：闭合薄壁回转体 → **一次旋转成形**（外轮廓 + 内腔同时旋出），不用抽壳；肩部用两段相切圆弧保证 G1 连续，避免折线采样留下棱边。
- 证据：包围盒 `66 × 235 × 66`、1 实体、满口容量 `568.4 ml`、材料体积 `51,381.767 mm³` 对 Pappus 解析值 `51,381.777 mm³`、审查 100。
- 已知简化：瓶口螺纹是 3 道环形棱，不是真实螺旋牙；瓶盖未建模。

### 04 手机支架：照片反求 + 可动装配

- 输入是 15 张实物照片；先用接触表筛选，选出 3 张（俯视、侧面细节、收拢细节），再按半幅裁切读结构。
- 反求链：照片 → 结构假设 → 关键尺寸（底座直径按标尺实测约 10.3 cm，修正原估 Ø110 为 Ø104）→ 用户确认螺钉数量/布局（3 颗 120°，落在脚垫之间）→ 8 个零件。
- 装配不是“摆个样子”：永久配合只保留同心 + 平面重合，转动自由度放开；姿态用临时角度配合驱动后删除，装配体可直接拖动。
- 证据：展开/收拢两姿态均审查 100、干涉 **0** 处；8 个零件 + 2 个装配全部重新打开验证。
- 已知偏差：手机尺寸按 OPPO Reno 14 厂商标称值（`estimated`），不是实测；托钩、背板经过多轮干涉修正。

## 3. 复现前必读

1. **先复制整个实例目录**到自己的工作区再重跑。脚本会按固定文件名写模型/预览，直接在原目录跑会覆盖随包交付的成果。
2. **SolidWorks COM 写操作必须串行**：不要同时开多个脚本，也不要在脚本运行期间手动操作同一文档。
3. 脚本会自动发现技能目录，顺序为：
   - 环境变量 `SOLIDWORKS_PLUS_PLUS_SKILL_DIR`（旧变量 `SOLIDWORKS_MODELING_SKILL_DIR` 仍作为回退）；
   - 仓库布局 `<repo>/showcase/<case>/` → 上两级找 `skills/solidworks-plus-plus`；
   - 发布包布局 `<release>/showcase/<case>/` → 上两级找 `solidworks-plus-plus`；
   - `~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills`（以上均含旧目录名 `solidworks-modeling` 回退）。
4. 模型是 **SolidWorks 2023 格式**；更高版本可以直接打开，低版本不能。
5. `review` 100 分只代表**规则检查**通过；`manual_review_required` 仍为 `true`，最终几何是否符合意图要目视预览图确认。
6. 只有齿轮实例带工程图 PDF；其余三个是示意件，交付物是模型 + 预览 + 证据。
