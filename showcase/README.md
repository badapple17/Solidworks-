# SolidWorks++ 实战实例（showcase）

六个**真实任务**，不是演示玩具。它们由 **DeepSeek V4 系列模型**（低成本档位）在只调用本技能的条件下完成，保留了当时的建造脚本、输入分析、关键预览、审查报告和 PDF。

> **性价比说明**：这些模型不是顶级推理模型反复精修出来的“展示件”，而是低成本模型按技能流程跑出来的交付。能成立靠的是**模式判定、提问、脚本封装和证据门禁**，不是模型本身记住了多少 API。

| 目录 | 任务 | 模式 | 输入 | 核心看点 |
|---|---|---|---|---|
| [01-spur-gear](01-spur-gear/) | 直齿圆柱齿轮 Z24 / m2.5 | A 示意 + 出图 | 文字需求 | 完整工程图链路：A3 第一角三视图、4 个尺寸、PDF 机器初筛 0 问题 |
| [02-car-wheel](02-car-wheel/) | 汽车轮毂，前后双面 5 辐 | A 示意 | 文字需求 + 用户反馈 | 过程门禁实例：单面 → 双面重建；体积与解析值误差 0.00000% |
| [03-plastic-bottle](03-plastic-bottle/) | 百岁山风格 PET 水瓶 570 ml | A 示意（设计自由度） | 文字需求 | 一次旋转成形；Pappus 解析体积与实测完全对上 |

## 1. 每个实例都包含什么

所有实例统一使用下面的目录语义：

```text
<case>/
├── README.md              # 任务、参数、验证证据、限制、复现命令
├── scripts/ 或 *.py       # 当时的建造 / 验证脚本（已改为可移植路径）
├── inputs/                # 原始输入（试卷、STEP 标准件、照片），如有
├── deliverables/          # 交付模型：parts/、assembly/、drawings/
├── previews/              # 四视图 / 等轴测预览与联系表
├── evidence/              # 审查报告、干涉分类、运动/验证证据
└── work/                  # 建造过程记录（build_status.json 等）
```

`previews/` 里是 `run_review()` / `save_preview()` 导出的原始预览；`evidence/` 里是门禁脚本写出的机器可读报告。

## 2. 六个实例分别证明了什么

### 01 齿轮：从“示意”走到“可出图”

- 文字需求只给了齿轮类型和大概规格，技能按 **A 模式**处理：不追问具体数值，但把每个取值的来源写进参数表。
- 齿形是**渐开线采样**（每齿 18 点、24 齿共 432 段），不是圆弧 approximation。
- 出图走 **B 路线**（模型 → 图）：`sw_three_view.py` 自动建 A3 第一角三视图、导入模型尺寸、自动排列。
- 证据：包围盒 `65 × 65 × 20`、1 实体、φ20 孔 + φ36 轮毂、审查 100、图纸 4 个尺寸、PDF 机器初筛 **pass（0 问题）**。
- 遗留限制：4 个尺寸只覆盖轮毂与齿圈主参数，不构成加工用完整尺寸链。

### 02 轮毂：用户反馈触发的 G2 过程门禁

- v1/v2 只做了单面轮辐，用户反馈“轮子只有一面，另一边是空的”。
- 这属于**拓扑改变**：技能按 G2 门禁停下，重建为前后对称双面结构，辐窗/中心孔/螺栓孔一次贯穿两面。
- 证据：包围盒 `470 × 470 × 200`、1 实体、体积 `7,811,777.122 mm³` 对解析值 `7,811,777.086`（误差 0.00000%）、审查 100。

### 03 水瓶：把“设计自由度”讲清楚

- 用户只给了“百岁山风格”的文字需求，没有尺寸。技能把所有尺寸标为 `user_delegated`（用户授权自定），但**结构约束**（肩部相切、壁厚、颈/口尺寸、容量）必须明确记录。
- 建模路线：闭合薄壁回转体 → **一次旋转成形**，不用抽壳；肩部用两段相切圆弧保证 G1 连续。
- 证据：包围盒 `66 × 235 × 66`、1 实体、材料体积 `51,381.767 mm³` 对 Pappus 解析值 `51,381.777 mm³`、审查 100。

### 04 手机支架：照片反求 + 可动装配

- 输入是 15 张实物照片；先用接触表筛选，选出 3 张（俯视、侧面细节、收拢细节），再按半幅裁切读结构。
- 反求链：照片 → 结构假设 → 关键尺寸（底座直径按标尺实测约 10.3 cm，修正原估 Ø110 为 Ø104）→ 用户确认螺钉数量/布局（3 颗 120°，落在脚垫之间）→ 8 个零件。
- 装配不是“摆个样子”：每个转动件只留一个绕铰链轴的转动自由，其余自由度用轴向定位配合消掉；姿态用临时角度配合驱动后删除。
- **运动学探针**（`a04_motion_check.py`）修掉了交付后才发现的轨迹错误：顶部关节被拖动时会左右平移、整台支架会整体漂移。修复后 8 个非固定件三向强推位移全部 `0.000 mm`，铰链实转 `5.000°`、转轴 `(1,0,0)`。
- 证据：展开/收拢两姿态均审查 100、干涉 **0** 处。

### 05 减速器：图纸自相矛盾时，保留图纸并登记冲突

- 10 个零件覆盖套筒、上下盖、齿轮副（m1.25 z30 / 内齿 z90，中心距 37.5）、固定轴、传动轴、唇形密封圈和钣金盖板；三套装配各 9 个组件；另出 A2 装配图 + 2 张 A3 零件图。
- 透明涂色不是“随便上色”：先复制原件再在副本上按组件设色 + 透明度，回读 `MaterialPropertyValues` 逐件校验（0.82/0.82/0.35/0.10）。
- 试卷图自带尺寸冲突（上盖凸台伸进旋转套、固定轴头超出齿圈齿顶），技能**不改试卷尺寸**，而是把 12 处干涉按组合登记体积上限：新组合或超上限即失败。
- 真实修正：侧窗用 60 段折线近似圆弧时碎成 **61 个实体**，改成两段真圆弧 + 两条径向线后恢复 1 个实体。

### 06 齿轮油泵：输入最全的一次，也是最接近“一次做对”的一次

- 7 页试卷 + 19 项明细栏 + 7 个 STEP 标准件，尺寸几乎不需要回头问；19 个零件、3 套装配（每套 26 个组件）。
- 装配不用配合：所有零件按同一世界系建模，26 个组件由 `IComponent2.Transform2.ArrayData` 显式定位；列主序、米制平移、SAFEARRAY 三个坑都由探针实测后写进脚本。
- 齿轮轴来自 STEP，两轮按**半个齿距**相位对齐（`360/14/2`），保证啮合。
- 证据：三套装配重开回读 26 组件、包围盒全部 `match=True`、`11_body` 透明度 0.8，`ALL PASS: True`。

## 3. 六个实例得出的结论（重要）

把六个实例放在一起看，正确率和“输入信息量”几乎是一条直线：

| 输入信息量 | 实例 | 结果 |
|---|---|---|
| **高**：零件图 + 装配图 + 明细栏 + STEP | 05、06（考试题） | 尺寸可追溯，建造过程几乎不需要补充提问；剩余偏差只来自试卷图自身的冲突 |
| **中**：多视图 + 标注尺寸 | 01、02、03 | 一轮提问定模式后即可施工，证据链完整 |
| **低**：15 张照片 + “尺寸随意” | 04（照片反求） | 结构能读对，但主尺寸、螺钉布局、手机型号都得回头问用户才定得下来 |

由此得到两条写进技能的规则：

1. **输入越详细、越全面，建出的模型越接近正确。** 图纸齐全时，模型的工作是“读数 + 施工 + 验证”，不是“猜”。
2. **简单模型反而更容易“发懵”和瞎编。** 当一个零件很简单、用户又只说“随便做一个/看着像就行”时，信息量和质量要求同时含糊——模型会按常见做法把看不清的结构、数量、比例自己补出来。**所以任务越简单、需求越含糊，越要多提问**：至少问清用途/受力、关键接口（孔距、轴径、安装面）、哪些尺寸允许自定、质量档位（示意 / 能装配 / 能加工）。这四项没答全，不允许开工。

这两条已经写进 `skills/solidworks-plus-plus/references/modes-and-questions.md` §2.0（提问强度与输入信息量成反比）和 SKILL.md 黑名单。

> 换句话说：技能不能保证“信息少也做对”，但能保证**信息少时先问、问完再建，并且把假设标出来**。六个实例里没有一个是靠模型“猜对”的——要么图纸给全了，要么提问补全了。

## 4. 复现前必读

1. **先复制整个实例目录**到自己的工作区再重跑。脚本会按固定文件名写模型/预览，直接在原目录跑会覆盖随包交付的成果。
2. **SolidWorks COM 写操作必须串行**：不要同时开多个脚本，也不要在脚本运行期间手动操作同一文档。
3. 脚本会自动发现技能目录，顺序为：
   - 环境变量 `SOLIDWORKS_PLUS_PLUS_SKILL_DIR`（旧变量 `SOLIDWORKS_MODELING_SKILL_DIR` 仍作为回退）；
   - 仓库布局 `<repo>/showcase/<case>/` → 上两级找 `skills/solidworks-plus-plus`；
   - 发布包布局 `<release>/showcase/<case>/` → 上两级找 `solidworks-plus-plus`；
   - `~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills`（以上均含旧目录名 `solidworks-modeling` 回退）。
4. 模型是 **SolidWorks 2023 格式**；更高版本可以直接打开，低版本不能。
5. `review` 100 分只代表**规则检查**通过；`manual_review_required` 仍为 `true`，最终几何是否符合意图要目视预览图确认。
6. 01–04 以示意/照片为主；05、06 是 B 模式考试件，另有 `evidence/` 里的机器门禁报告。05 带 3 张工程图（A2 装配图 + 2 张 A3 零件图），06 不出图。
7. 脚本结束统一调用 `session.finish()`：关闭文档并退出脚本启动的 SolidWorks 实例，不留后台进程占用交付文件。若历史遗留实例仍锁文件，先跑 `<skill>\scripts\sw_release.py --quit`。
